Lesson 1 of 3Networking for AI

1. The Four Networks in an AI Data Center

Network Purpose
Compute network Minimizes bottlenecks and maximizes performance for AI workloads (GPU-to-GPU traffic between jobs). Adds redundancy for hardware failures and keeps costs down
Storage network High-throughput access to shared storage. Benefits from high bandwidth and advanced fabric management
In-band management network Connects to the management nodes. It's the main network for everything except job traffic and high-speed storage: SSH, DNS, job scheduling, the NFS home file system, and external services (NGC registry, code repos, data sources)
Out-of-band (OOB) management network Remote management even when servers are offline or unreachable in-band: remote power control, remote serial console, temperature and power sensors

Why keep management separate? So management traffic doesn't interfere with cluster services or user jobs.

2. Why AI Needs a Special Network

  • GPU utilization must stay as high as possible. GPUs have so many processing elements that they need constant feeding with data.
  • Moving data in and out of the GPU is expensive in time.
  • Models and datasets keep growing, and many models run across multiple GPU nodes, so data must move between GPUs.
  • Performance comes from the interplay of data management, GPU utilization and network configuration, not hardware alone.
  • Inside a server, the CPU, memory and storage must also keep up so the GPU doesn't sit idle.

Network factors that affect performance

  1. Network topology
  2. Bandwidth and latency
  3. Network protocols
  4. Data transfer techniques
  5. Management methods

3. Traditional vs. AI-Optimized Network

Traditional / cloud ("north-south") AI-optimized ("east-west", GPU-to-GPU)
Carries Storage, control traffic. A legacy network GPU-to-GPU traffic and high-speed storage
Transport TCP RDMA
Loss Can be lossy Lossless (needed for RDMA)
Jitter Tolerates high jitter Must avoid jitter
Latency Not critical Low latency
Applications Many independent apps with no dependencies Like HPC: nodes depend on each other
What limits it Individual app performance The slowest element sets the speed of the whole cluster: a slow CPU, high jitter or high tail latency
Key metric — How long an AI training job takes from start to finish

4. AI Factories vs. AI Clouds

AI factory AI cloud
Used for The largest training jobs: building and refining huge foundation models at extreme scale Hyperscale, multi-tenant services running many smaller jobs
Tenants and jobs One tenant, one or a few jobs at a time Many users, many jobs
Network NVLink + InfiniBand with in-network computing Traditionally Ethernet
What's changing — AI clouds now sometimes need to run large generative AI workloads, and traditional Ethernet is too slow for them. That's the reason for AI-optimized Ethernet (Spectrum-X, covered later in this unit)

Key Terms

  • Compute / storage / in-band / out-of-band networks: the four networks in an AI data center.
  • Out-of-band (OOB): management access that works even when the server OS is down (power, console, sensors).
  • North-south vs. east-west: traffic in and out of the data center vs. server-to-server traffic inside it.
  • RDMA: remote direct memory access, which needs a lossless network.
  • Jitter / tail latency: variation in delay / the slowest responses. Both slow down an entire AI cluster.
  • AI factory vs. AI cloud: a single tenant running giant jobs vs. many tenants running smaller jobs.

Exam Tips

  • Know the four networks: compute, storage, in-band (SSH, DNS, scheduling, NFS home, NGC) and out-of-band (power, serial console, sensors, works when the server is offline).
  • Traditional networks use TCP and tolerate jitter. AI networks use RDMA, are lossless and low-jitter.
  • In an AI cluster, the slowest node or link sets the pace. The key metric is job completion time.
  • AI factories run on NVLink + InfiniBand. AI clouds run on Ethernet, which now needs to be AI-optimized.

Lesson 2 of 3InfiniBand and Ethernet

1. InfiniBand

  • A networking technology built for high throughput and low latency with minimal processing overhead.
  • The spec is maintained by the InfiniBand Trade Association (IBTA). It covers everything from the hardware layer to the application layer.
  • It connects compute and storage at high speed and includes intelligent offload features.
  • A favorite of traditional HPC (scientific simulations on parallel clusters), also used in cloud data centers and GPU AI.
  • The most deployed high-speed interconnect for large-scale ML, for both training and inference.

RDMA: InfiniBand's key feature

Term Meaning
DMA (direct memory access) A device, such as a GPU or network adapter, reads and writes host memory directly without the CPU
RDMA (remote DMA) Accesses memory on a remote system without interrupting that system's CPU
HCA (host channel adapter) An InfiniBand network adapter. It has hardware offload and bypasses the TCP/IP stack completely, for faster data movement with less CPU overhead

RDMA benefits:

  • Efficient data transfer: OS bypass gives the fastest possible access to remote data.
  • Efficient computing: lowers power, cooling and space needs.
  • Supports message passing, sockets and storage protocols.
  • Supported by all major operating systems.

2. Ethernet

  • Introduced in 1979 and standardized as IEEE standards in the 1980s. It defines how devices format and send data on a LAN.
  • The dominant LAN technology, because it keeps getting faster while staying backward compatible: 10 Mb/s → 100 Mb/s (mid-1990s) → up to 400 Gb/s today.
  • Ethernet is general-purpose, covering home, corporate LAN and data center. InfiniBand has one goal: the highest-performance data center interconnect.

RoCE (RDMA over Converged Ethernet)

  • Brings RDMA to Ethernet networks.
  • It takes the InfiniBand packet header and wraps it in a UDP header carried over Ethernet.
    • UDP is simple, flexible and compatible with legacy hardware.
    • UDP encapsulation lets RoCE cross Layer 3 (routed) networks.
  • RoCE is open source and a formal IBTA standard. It's increasingly important for AI, storage and big data, although InfiniBand's native RDMA is still leaner.

3. GPUDirect RDMA

  • A direct, peer-to-peer data path between GPU memory and NVIDIA network adapters, so GPUs in different servers can talk directly.
  • Minimizes CPU use and avoids buffer copies through system memory.
  • NVIDIA adapters combine data and send smart interrupts, using close to 0% of CPU cycles.

Packet flow

Step Without GPUDirect RDMA With GPUDirect RDMA
1 The HCA receives packets from the remote node The HCA receives packets
2 Packets cross PCIe and are copied to system memory Packets go straight to GPU memory
3 The CPU handles them —
4 Copied again over PCIe to GPU memory —

What it saves: whole copy operations, PCIe transactions and CPU usage, and it lowers end-to-end latency.

Key Terms

  • InfiniBand (IB): a low-latency, high-throughput interconnect standardized by the IBTA.
  • HCA: host channel adapter, the InfiniBand NIC.
  • DMA / RDMA: direct memory access, local / remote, without the CPU.
  • OS bypass: data moves without going through the kernel's TCP/IP stack.
  • RoCE: RDMA over Converged Ethernet, an IB header wrapped in UDP over Ethernet.
  • GPUDirect RDMA: the NIC reads and writes GPU memory directly, skipping system memory and the CPU.

Exam Tips

  • InfiniBand is the most deployed interconnect for large-scale ML. Its spec comes from the IBTA.
  • RDMA lets one system access another's memory without involving its CPU. HCAs bypass TCP/IP.
  • RoCE = an InfiniBand header in UDP over Ethernet. It can be routed across Layer 3.
  • GPUDirect RDMA skips the copy into system memory and the CPU, giving lower latency and less CPU and PCIe load.
  • Ethernet is general-purpose and backward compatible (up to 400 Gb/s). InfiniBand is purpose-built for top performance.

Lesson 3 of 3NVIDIA Networking Portfolio

1. The Network Is the Foundation

  • "The data center is the new unit of compute", and the network is what makes it work as one system.
  • Agentic AI and reasoning models are data- and latency-sensitive, not just compute-heavy. They span thousands of GPUs across racks and rows.
  • NVIDIA offers end-to-end InfiniBand and Ethernet solutions.

Where each technology fits

Technology Role Direction
NVLink Scale up: GPUs in a server, or in tightly coupled servers, behave like one large memory and compute pool. Essential for model parallelism Inside the node or rack
InfiniBand (Quantum) and Spectrum-X Ethernet Scale out: the high-speed east-west compute fabric between nodes, for multi-node training and inference East-west
BlueField DPU Secures and accelerates north-south traffic: user access, control planes, storage fabrics. Offloads networking, security and storage from the CPU North-south

2. Spectrum-X: Ethernet Built for AI

  • The first Ethernet platform designed specifically for AI clouds. It delivers near-perfect bandwidth and very low latency.
  • The secret is NVIDIA's RoCE extensions, which go beyond standard RoCE:
Extension What it does
RoCE Adaptive Routing Fine-grained, dynamic load balancing. It reroutes RDMA traffic around congestion, choosing paths from live switch state (queue occupancy, port utilization)
RoCE Congestion Control Limits the injection rate of flows at congested ports. This means fewer packet drops on lossy networks, less congestion spreading on lossless ones, less buffer use, lower latency and better burst tolerance. It also provides performance isolation
  • These extensions need the Spectrum-4 switch AND the BlueField-3 DPU working together. They're unique to NVIDIA.
  • It's tuned and validated across the full NVIDIA stack, but it's still standards-based Ethernet, interoperable with any Ethernet device.

3. Quantum-X800: InfiniBand for Trillion-Parameter AI

  • The next generation of Quantum InfiniBand. It's the highest-performance end-to-end 800 Gb/s networking.
  • Components:
    • the Quantum-X800 InfiniBand switch
    • the ConnectX-8 SuperNIC
    • LinkX cables and transceivers
Component Key specs
Quantum-X800 switch 144 ports × 800 Gb/s. SHARPv4 in-network computing, adaptive routing, telemetry-based congestion control, performance isolation, and a dedicated port for UFM (Unified Fabric Manager)
ConnectX-8 SuperNIC Up to 800 Gb/s over InfiniBand and Ethernet. PCIe Gen6, up to 48 lanes, which allows PCIe switching inside GPU systems

4. Co-Packaged Optics (Silicon Photonics)

  • Replaces pluggable transceivers with silicon photonics in the same package as the switch ASIC.
  • Compared with traditional networks:
    • 3.5× better power efficiency
    • 10× higher network resiliency
    • 1.3× faster time to deploy
Switch Specs
Quantum-X Photonics (Quantum 3450-LD) 115 Tb/s InfiniBand, 144 × 800 Gb/s ports, liquid-cooled. Connects over 10,000 GPUs in a non-blocking two-level fat-tree at 800 Gb/s
Spectrum-X Photonics SN6810 128 × 800 Gb/s Ethernet
Spectrum-X Photonics SN6800 512 × 800 Gb/s Ethernet

Key Terms

  • Scale up vs. scale out: NVLink inside a node or rack vs. InfiniBand or Ethernet between nodes.
  • East-west / north-south: server-to-server traffic / traffic in and out of the data center.
  • Spectrum-X: NVIDIA's AI Ethernet platform (Spectrum-4 switch + BlueField-3).
  • RoCE Adaptive Routing / Congestion Control: NVIDIA's dynamic load balancing / injection-rate limiting.
  • Quantum-X800: NVIDIA's 800 Gb/s InfiniBand platform.
  • SHARP: in-network computing that runs collective operations inside the switch.
  • UFM: Unified Fabric Manager, which manages InfiniBand fabrics.
  • SuperNIC: ConnectX-8, an 800 Gb/s NIC for IB or Ethernet.
  • Co-packaged optics: optics built into the switch package instead of pluggable modules.
  • Fat-tree: a non-blocking multi-level switch topology.

Exam Tips

  • NVLink scales up. InfiniBand and Spectrum-X scale out (east-west). BlueField handles north-south.
  • Spectrum-X needs Spectrum-4 + BlueField-3 for RoCE Adaptive Routing and Congestion Control, and it's still standard, interoperable Ethernet.
  • Adaptive routing balances load dynamically using switch queue and port state. Congestion control limits injection rate at hot ports.
  • Quantum-X800 = 144 × 800 Gb/s + SHARPv4 + UFM. The ConnectX-8 SuperNIC does 800 Gb/s on IB or Ethernet over PCIe Gen6.
  • Co-packaged optics give 3.5× power efficiency, 10× resiliency and 1.3× faster deployment.
